# 测试：方块计划刻调度器

本目录存放方块计划刻调度器的单元测试数据，按测试主题组织。当前包含两个数据集：区块数据的（反）序列化（专项约定见 `README_（反）序列化.md`）与调度器运行时（专项约定见 `common/调度/README.md`）。

被测的两个区块数据实现是：

- 打包实现 `PackedBlockTickDatum`：一条计划刻压进一个 `long`，区块数据以 `queue` 长整型数组保存；
- 装箱实现 `BoxedBlockTickDatum`：一条计划刻是一个 `IScheduledTick` 对象，区块数据以 `entries` 复合标签列表保存。

### 时间的环语义

计划刻的时间字段沿用世界总时间（`getTotalWorldTime`），它是 64 位计数器——溢出归零是合法状态，因此实现把时刻当作 **2^64 环上的点**处理，样例也按这个模型书写与验算：

- **环上只有差值有意义**：两个时刻不做大小比较，一切判断基于两个时刻相减得到的时间差（`a - b` 溢出后的结果就是从 b 到 a 的前向距离，始终精确）。加法、减法在环上天然正确，溢出的进位自然舍弃；
- **合法未来窗口是 `[0, 2^31-1]`**（`schedule` 的 delay 参数是 int，这是窗口宽度的来源）：从当前时刻到触发刻的前向距离为 0 即当刻到期，落在 `[1, 2^31-1]` 才是未来，窗口外一律视为到期——其中既包括真实过期的条目，也包括时间差接近一整环、数值上表现为遥远未来的条目，两者的处置相同；
- **装箱格式的 `t` 字段是 int**：触发刻与存盘时间的时间差装不进 int 时，统一压成 `Integer.MIN_VALUE` 标记值（含义为"严重过期"），读档后立即到期。装得进 int 的负差值则如实保存。过期条目本身两个实现都能精确表示（打包实现的 baseTime 落后当前时间最多 2^31，触发刻在基准时间之后即可，不要求在当前时间之后），且容忍边界同为 2^31——装箱来自 `t` 的 int 位宽，打包来自基准时间只前进的约束。丢失过期时长的只有三个具体时点：打包重设基准时间时新基准时间之前的条目归 0、打包经迁移/V1 路径加载时基准时间被选为存盘时刻、装箱存盘时时间差超出 int；
- **打包实现读入 V1 与装箱数据的旧条目时，窗口外的 delay 一律归 0**：负差值与该标记值都落在窗口外（触发刻=基准时间，读档立即到期）；
- **样例书写提示**：环上的点两侧都按无符号十进制书写——SNBT 用 `uL` 字面量（如 `9223372036854775800uL`），YAML 直接写无符号大数（超出有符号 long 范围的值由测试的 YAML 构建器按无符号解析后装入 long 字段，`时` 与 `time` 均适用）。越过 2^63 的点只是符号位翻转，不是归零；归零点在 2^64≡0 处，越过它的触发刻回到小正数。两者都是环上的正常状态，不是错误。

### SNBT 辅助函数

`.snbt` 文件里可以调用 `可测试的计划刻` 用 `@SNBTFunction` 注册的三个函数，免去手写打包值。这些函数由 `方块计划刻调度器测试` 在 `beforeAll` 阶段注册，继承该基类的测试都可使用。

| 函数 | 签名 | 产出 |
|---|---|---|
| `blockOf` | `blockOf(词块:String)` | 该方块在注册表中的数字 ID（`Int`） |
| `tick` | `tick(delay:Int, 级:Byte, pos:[I;x,y,z], 词块:String)` | V2 打包格式的一个 `Long` 值 |
| `packPosAndPri` | `packPosAndPri(级:Byte, pos:[I;x,y,z])` | V2 装箱格式的 `p` 字段（`Long`） |

- `tick` 的位排布是 `delay<<32 | 级<<28 | y<<20 | z<<16 | x<<12 | 方块ID`，校验 `级` 在 0–15、`x` 与 `z` 在 0–15、`y` 在 0–255。`delay` 按无符号读取，达到或超过 `2^31` 的延迟要写 `u` 后缀；
- `packPosAndPri` 的位排布是 `级<<40 | x<<36 | z<<32 | y`，校验 `级` 在 0–15、`x` 与 `z` 在 0–15；`y` 占满低 32 位且不作范围校验，因此越界与负数 `y` 都能表达；
- `blockOf` 按 `方块原料._全构造器_` 的完整词块映射取 ID（`tick` 取 ID 走同一条路径），而 YAML 侧的 `块` 字段按 `upon` 指定的空间构造器取方块（缺省 `天圆地方:scheduler`，含常用基础映射与猹、鲁迅系列词块）。词块名精确到方块状态，但计划刻只入队方块——`块` 字段优先写无下标的词块（如 `猹`）；`鲁`、`讯` 虽同属鲁迅方块的不同状态，仍按 `鲁`/`讯` 书写以保可读。（反）序列化侧要求输入与答案两边用同一个词块名——不是因为不同就会比较失败（同方块的不同状态映射到同一方块），而是避免读样例时产生疑惑（目前这两侧尚无带下标的用例）。

### data.schema.json

`data.schema.json` 是 `计划刻数据` 对应的 JSON Schema（draft-07），约束 YAML 样例的字段：

- `upon`：字符串，空间构造器 ID，缺省 `天圆地方:scheduler`；
- `time`：整数，缺省 `0`。序列化输入里它是 `baseTime`，即世界总时间；反序列化答案里不参与比较，可省略；
- `原点`：所有 `于` 的公共基点，逐维相加得到实际坐标，缺省 `[0,0,0]`；
- `使用网格坐标`：为 `true` 时 `原点` 与 `于` 都按网格坐标 `[层, 行, 列]` 书写，先转换为游戏坐标再相加，缺省 `false`；
- `ticks`：计划刻列表，每条必填 `于`（`[x, y, z]` 三元整数数组）、`块`、`时`，可选 `级` 与 `创时`（运行时样例的入队时刻，见 `common/调度/README.md`）。`时` 是绝对触发刻而非延迟；`级` 取 `计划刻等级` 的十六个枚举名（`危急0` 至 `松弛15`，名字后缀的数字即存储值），缺省 `中上7`。

样例 YAML 首行写 `# yaml-language-server: $schema=../../data.schema.json` 供编辑器实时校验，测试本身不读这一行。
