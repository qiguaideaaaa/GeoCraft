# 样例：鲁迅

<!-- 文档 Claude Generated，样例本身由作者设计 -->

同一场景内验证三件事：同刻内优先级顺序、鲁迅方块的触发计数、严重过期标记值的立即消费。核心手法是把四只猹拆成两条互不补救的验证线，各配独立的算术预算。

## 布局与计划

单层十字，中心鲁4（水平四方、减一），四周两只猹4（上 [2,1,2]、右 [2,2,3]）与两只猹5（左 [2,2,1]、下 [2,3,2]）。世界时间从 0 起，测试时段 `[0,32]`。

| 波次 | 计划 | 说明 |
|---|---|---|
| 首刻入队 | 鲁 `时 3` `级 较高6`；四只猹各 `时 3` | 五条同刻，鲁的优先级高于猹的缺省中上7 |
| `创时 5` | 左、下两只猹 `时 19` | 只负责清除猹5 线的第二波计划 |
| `创时 16` | 鲁 `时 -2147483648` | 严重过期标记值，入队即到期 |

## 时间线（正确路径）

- **t=3**：五条计划同刻到期。鲁凭优先级**先**消费：四只猹全部减一（猹4→猹3、猹5→猹4）。随后四只猹自己的计划消费，此刻低四位为 3——两只猹3（原猹4）命中自清；两只猹4（原猹5）不同余，站立。
- **t=5**：第二波入队（此时目标仍是猹，入队成功）。
- **t=16**：严重过期的鲁入队。时间差 −2147483664 装不进 int，入口压成 `Integer.MIN_VALUE`，打包侧负存储值归 0——**当刻立即消费**：两只幸存猹4→猹3。
- **t=19**：低四位为 3，第二波清除两只猹3。全场清空。

## 故障与现场

| 故障 | 现场 |
|---|---|
| 鲁首刻未触发 | 猹4 线保持 4，t=3 不同余，且该线无第二波——上、右两只猹永久幸存 |
| 同刻顺序颠倒（猹先于鲁消费） | 猹4 线 t=3 时仍是 4 不同余，随后才被拨成 3，无人再收——幸存 |
| 严重过期的鲁未立即消费（压缩或归 0 失效） | 猹5 线停在 4，t=19 不同余——左、下两只猹幸存 |
| 任何一次鲁触发重复 | 对应线多减一格，清除刻不同余——幸存 |
| 第二波丢失 | 猹5 线没有计划再来清除——幸存 |

两条线互不补救，幸存者的位置（上下 vs 左右）直接指认断裂的是哪条链。

## 设计要点

- 猹4 线的自清**依赖**"鲁先拨、猹同刻后死"的顺序，且不配补救计划——这是全部样例中唯一钉住同刻优先级顺序的位置；
- 猹5 线的清除刻 19 只在"恰好被拨两次"后同余——鲁的每次触发都是算术上不可替代的一环；
- 该严重过期条目直接使用序列化侧"严重过期"的字面值 `Integer.MIN_VALUE`，一条链同时压过入口 int 压缩、运行时负存储值归 0、"标记值=立即到期"三段语义。
