# 样例：重设基准时间

<!-- Claude Generated -->

利用时段跳跃把世界时间与队列基准时间的差距拉过 2^31，验证打包队列的重设基准时间（updateBaseTime）：重设基准时间必须真的发生、旧条目在重设基准时间中被正确处置、新条目的存储值不因与基准时间差距过大而截断。这是唯一让"当前时间 − 基准时间"超出 int 范围的样例。

## 布局与计划

单层两格 `猹0 猹2`，世界时间从 0 起，测试时段 `[[0,1], [4294967312,4294967316]]`（第二区间起点 2^32+16，时钟瞬移抵达）：

| 位置 | 方块 | 创时 | 时 | 含义 |
|---|---|---|---|---|
| [1,1,1] | 猹0 | 0 | 2147483647 | int 最大延迟入队，横跨跳跃存活的旧条目 |
| [1,1,2] | 猹2 | 4294967312 | 4294967314 | 跳跃后入队，与基准时间的差距已超 2^31，入队即触发重设基准时间 |

## 时间线（正确路径）

- **t=0**：第一条入队，基准时间定为 0，存储值 2147483647。
- **跳跃至 t=2^32+16**（低四位 0）：第二条入队。此刻与旧基准时间相差 2^32+16，超过 2^31−1，入队路径触发重设基准时间：基准时间改为当前时刻，旧条目的触发刻（2147483647）已在新基准时间之前，存储值归 0——当刻消费，猹0 命中自清。第二条按新基准时间计存储值 2。
- **t=2^32+18**（低四位 2）：第二条消费，猹2 命中自清。

## 故障与现场

| 故障 | 现场 |
|---|---|
| 重设基准时间条件不触发（与基准时间的差距比较写错） | 第二条的存储值 2^32+18 被 32 位截断成 18，在跳跃刻提前消费（低四位 0≠2）——猹2 幸存 |
| 重设基准时间时旧条目处置错误（丢弃或存储值算错） | 猹0 幸存或在错误时刻被消费而不清除 |
| 跳跃后过期条目不消费 | 猹0 幸存 |

## 职责边界

覆盖重设基准时间的触发比较与旧条目归 0，重设基准时间缺失导致的存储值截断会被检出；堆内部比较在重设基准时间后仍是小存储值，大存储值的堆序验证需要"跳跃 + 长延迟"组合的更深样例，暂未纳入。
