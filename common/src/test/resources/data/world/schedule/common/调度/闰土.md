# 样例：闰土

<!-- 文档 Claude Generated，样例本身由作者设计 -->

第一个把"计划刻执行中途入队"纳入测试的样例：闰土在被消费时给自己 schedule 后续计划——这条重入路径驱动器碰不到（驱动器的入队检查发生在消费之前）。同场并测同刻优先级链与去重键的方块精细度。

## 布局与计划

三层 3×3，无原点偏移。关键格：`[1,2,2]` 参照猹2（闰土下方）、`[2,2,2]` 闰2（延迟 2）、`[2,2,3]` 猹1、`[3,2,3]` 鲁x（朝下）。闰土上方 `[3,2,2]` 初始为 〇。测试时段 `[0,5]`。

| 条目 | 位置 | 时 | 创时 | 级 | 职责 |
|---|---|---|---|---|---|
| 闰 | [2,2,2] | 0 | 0 | 缺省中上7 | 首次消费：种猹 + 给自己排 t=2 |
| 鲁x | [3,2,3] | 0 | 0 | 中下8 | 把 [2,2,3] 的猹1 拨成猹0 |
| 猹 | [2,2,3] | 0 | 0 | 低10 | 当刻自清（低四位 0） |
| 石 | [3,2,2] | 2 | 0 | 松弛15 | 去重精细度线（见下） |
| 猹 | [3,2,2] | 2 | 0 | 松弛15 | 清掉闰土种下的猹 |
| 猹 | [1,2,2] | 2 | 0 | 松弛15 | 清掉参照猹 |

创时核对：(层2, 闰) 键为驱动条目【创0→t0】与自计划【t0→t2】首尾相接；([3,2,2], 猹) 与 ([3,2,2], 石) 各一条，键含方块不冲突。另有一条**系统内生成**的计划：闰土 t=0 被消费时自 schedule 的 `时 2`（yaml 里以注释形态展示，写的是等效的驱动器语言——真正的入队必须由闰土在消费中完成）。

## 时间线（正确路径）

- **t=0**（消费顺序 闰7 → 鲁8 → 猹10）：闰土见上方是 〇，往 `[3,2,2]` 种下猹2（出现时间 = (0+2)&0xF）并给自己排 t=2；鲁x 把 `[2,2,3]` 的猹1 拨成猹0；该猹的计划随后消费，低四位 0 命中自清。
- **t=2**（消费顺序 闰7 → 三条松弛15）：闰土复检——上方是种下的猹2、下方是参照猹2，断言相等通过；石计划消费时实际方块是猹，被消费侧验证跳过；两条猹计划分别清掉种猹与参照猹（低四位 2 命中）。
- 终态全清。

## 故障与现场

| 故障 | 现场 |
|---|---|
| t=0 猹先于鲁消费（优先级 8/10 颠倒） | `[2,2,3]` 消费时仍是猹1（1≠0）——幸存 |
| 去重键只认位置不认方块（猹计划在入队时被同位置的石计划挡掉） | 种下的猹2 无人清——`[3,2,2]` 幸存 |
| t=2 清除线抢在闰土之前（优先级 7/15 颠倒） | 种猹先被清，闰土见 〇 走种植分支：种猹4 并给自己排 t=4；t=4 复检时上方猹4、下方已是 〇——**断言立即失败**，消息带时间戳 |
| 闰土自计划迟到一刻（t=3 才执行） | 彼时上下均已清空，闰土种猹5 并给自己排 t=5——恰为终点刻不执行，猹5 留在 `[3,2,2]`——幸存 |

两条故障通道互补：优先级类故障走**即时断言**（立即失败、自带时间戳），时序类故障走**种植级联 + 窗口截断**（转换成终态幸存者）。

## 设计要点与边界

- 石线直接验证"去重精细到方块"：石与猹同位置各挂一条计划，二者都入队成功是绿的必要条件；石计划消费时的验证跳过是消费侧验证机制的建设性使用。
- **自计划早到不可见**：t=1 提前执行时上下都还是猹2，断言照过。中途入队正延迟条目的精确时刻，本样例不担保（由闰土复种样例的观察者与第二代参照覆盖）。注意"入队后当场递归执行"不属此列：闰土源码里 schedule 先于种猹，字面就地递归时上方仍是〇，会无限复种直到栈溢出——以崩溃报错的形式立即可见；真正不可见的是同刻批内被再次收集的形态。
- **自计划完全丢失不可见**：清除线会在 t=2 替它把种猹收走，断言从未执行也无人察觉。丢失检测需要"断言的缺席产生后果"的另一种构造，由闰土复种样例完成。
- 这两条边界连同"中途入队的负或 0 延迟条目的顺序与时刻一律不测"（设计规范），共同划定本样例的职责：它验证的是**正延迟自计划的准点性（不早于窗口内可检的一侧）与优先级链**，不是中途入队的全部语义。
