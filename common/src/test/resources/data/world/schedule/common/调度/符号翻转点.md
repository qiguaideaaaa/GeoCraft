# 样例：符号翻转点

<!-- Claude Generated -->

验证世界时间越过有符号 long 的符号翻转点 2^63 时，调度、到期判定与消费全程不受影响。

## 布局与计划

单层三格，世界时间从 T = 2^63−2 = 9223372036854775806 起，测试时段 `[0,5]`。三条计划均首刻入队：

| 位置 | 方块 | 时 | 触发刻低四位 |
|---|---|---|---|
| [1,1,1] | 猹e | T（翻转前） | e |
| [1,1,2] | 猹0 | T+2 = 2^63（恰在翻转点） | 0 |
| [1,1,3] | 猹2 | T+4（翻转后） | 2 |

时钟逐刻 +1 走过 2^63：数值上从最大正数跳到最小负数，环语义下只是普通一步。窗口内五个时刻的低四位依次为 e、f、0、1、2，两两互异——任何早消费或迟消费都落在不同余的时刻，猹不清除。

## 故障与现场

| 故障 | 现场 |
|---|---|
| 入口以有符号比较判过期（如 `时 <= 当前` 判定） | 翻转后触发刻被误判为远过去或远未来，对应猹幸存 |
| 消费早/迟一刻及以上 | 对应猹幸存（窗口内各时刻低四位互不相同） |
| 任一条计划丢失 | 对应猹幸存 |

## 职责边界

**本样例只覆盖入口的绝对时间减法**（`时 − 当前时间`）。打包队列内部全部是相对 baseTime 的小差值算术，翻转点不进入堆比较、到期判定与重设基准时间逻辑——那些内部无符号比较需要存储值或 elapsed 超过 2^31 的样例（重设基准时间类，待时段跳跃样例补充）才有判别力。与 `跨零` 镜像互补：本样例的"有符号绝对比较"故障在跨零线恰好表现正确，故该故障由本线独家负责。
