# 测试：方块计划刻调度器-区块-反序列化

## 测试描述

该测试用于验证两个区块数据实现从 NBT 读回计划刻的正确性。

测试流程是：把 `.in.snbt` 解析成一个 `NBTTagCompound`，交给 `deserializeNBT`，再把读出的队列与 `.ans.yaml` 描述的计划刻集合逐条配对比较（配上的从两边同时划去）（方块、坐标、触发刻、优先级四项全等即同一条，顺序无关）。装箱实现还会用文件名里的区块坐标构造一个 `EmptyChunk` 作为所在区块。

本 README 覆盖三处反序列化样例：

- `common/（反）序列化/`：两个实现各跑一遍，答案对两者同时成立；
- `packed/（反）序列化/`：只有打包实现会跑；
- `boxed/（反）序列化/`：只有装箱实现会跑。

输入可以是三种 NBT 形态之一：V1 遗留格式、V2 打包子格式、V2 装箱子格式。两个实现都能读全部三种，其中"打包实现读装箱数据"与"装箱实现读打包数据"是跨格式互读路径，也在本数据集覆盖范围内。

### 双实现语义差异现状

同一份输入在两个实现下的结果并不总是相同。以下差异决定了样例该放哪个目录：

| 情形 | 打包实现 | 装箱实现 |
|---|---|---|
| V1 条目的 `x`、`z` | 按 `&0xF` 取区块内坐标 | 原样保留为绝对坐标 |
| V1 条目的越界 `y`（小于 0 或大于 255） | 过滤丢弃 | 保留。装箱实现的用途就是兼容旧数据，对 `y` 不设范围限制 |
| V2 打包条目的坐标 | 就是区块内坐标（0–15） | 加上文件名区块的基址，还原成绝对坐标 |
| V2 装箱条目的坐标 | 按区块 (0,0) 还原，结果等于区块内坐标 | 加上文件名区块的基址 |
| V2 装箱条目的越界 `y` | 过滤丢弃 | 保留 |

由此，`common/` 下的样例要么把区块坐标定在 `(0,0)`，要么（V1 样例）保证绝对坐标已落在 0–15 内——`测试普通V1.1.1` 属于后者，它的坐标掩码前后一致，因此区块号取 `1.1` 也无妨。

另外两条与实现相关的语义未被本数据集覆盖：打包实现同样会丢弃方块 ID 超出 4095 的条目；`version` 大于 2 时两个实现都抛异常。

## 输入格式

输入是一个 `.in.snbt` 文件，内容为一个复合标签。`#` 起的注释在读取时被截去。三种形态的字段如下。

V1 遗留格式（`version` 小于等于 1，或没有 `version` 键）：

- `totalWorldTime`：`Long`，保存时刻的世界总时间；
- `block_updating_entries`：复合标签列表，每项含 `id`（`Int`，方块 ID）、`pos`（`[I;x,y,z]`，绝对坐标）、`time`（`Int`，相对 `totalWorldTime` 的延迟）。

V1 没有优先级字段，读出的条目优先级一律是 `中上7`。

V2 打包子格式（`version` 为 2、`type` 为 `1b`）：

- `baseTime`：`Long`，队列的基准时间；
- `queue`：`[L;...]` 长整型数组，每个字用 `tick(delay,级,pos,词块)` 写出，触发刻为 `baseTime` 加上按无符号读取的 `delay`。

V2 装箱子格式（`version` 为 2、`type` 为 `0b`）：

- `baseTime`：`Long`，写出时刻的世界总时间；
- `entries`：复合标签列表，每项含 `i`（`Int`，方块 ID）、`p`（`Long`，用 `packPosAndPri(级,pos)` 写出的坐标与优先级）、`t`（`Int`，相对 `baseTime` 的延迟，可为负）。

## 答案格式

答案是一个 `.ans.yaml` 文件，即一份 `计划刻数据`，字段见 `data.schema.json`。`ticks` 每项写 `于`、`块`、`时`（绝对触发刻），`级` 可省略（缺省 `中上7`）。答案侧的 `time` 不参与比较，一律省略。

坐标写绝对坐标还是区块内坐标，取决于跑这份样例的实现——见上文的差异表。需要绝对坐标且区块非 `(0,0)` 的样例，把 `原点` 设为区块基址 `[cx*16, 0, cz*16]`、`于` 写区块内坐标（两者相加即绝对坐标），与输入 SNBT 里的坐标直接对得上；V1 输入存的本来就是绝对坐标，其答案不这样拆。

## 输入输出样例 #1

### 输入 #1

```
{
  "version": 1,
  "totalWorldTime": 1000L,
  "block_updating_entries": [
    {"id": blockOf("〇"), "pos": [I;11,4,5], "time": 100},
  ]
}
```

### 答案 #1

```yaml
ticks:
  - 于: [11, 4, 5]
    块: 〇
    时: 1100
```

## 输入输出样例 #2

`packed/（反）序列化/测试V1.in.snbt` 摘录：

```
{
  "version": 1,
  "totalWorldTime": 1000L,
  "block_updating_entries": [
    {"id": blockOf("石"), "pos": [I;19,100,23], "time": 50},
    {"id": blockOf("〇"), "pos": [I;5,256,5], "time": 10}, #应丢弃
    {"id": blockOf("〇"), "pos": [I;5,-1,5], "time": 10} #应丢弃
  ]
}
```

### 答案 #2

对应答案摘录：

```yaml
ticks:
  - 于: [3, 100, 7]   # x: 19 & 0xF = 3，z: 23 & 0xF = 7
    块: 石
    时: 1050
```

## 输入输出样例 #3

`boxed/（反）序列化/测试装箱读打包.1.2.in.snbt`：

```
{
  "version": 2,
  "type": 1b,
  "baseTime": 400uL,
  "queue": [L;
    tick(5u, 7b, [I;0,10,0], "石"),
    tick(9u, 6b, [I;15,20,15], "圆"),
    tick(0u, 7b, [I;8,0,8], "基")
  ]
}
```

### 答案 #3

对应答案摘录：

```yaml
ticks:
  - 于: [16, 10, 32]   # x: (1<<4)+0，z: (2<<4)+0
    块: 石
    时: 405
```

## 说明/提示

### 样例 1 解释：

`common/（反）序列化/测试普通V1.1.1` 是 V1 格式的最小样例。触发刻由 `totalWorldTime` 加条目的 `time` 得到，即 `1000 + 100 = 1100`；V1 没有优先级字段，答案省略 `级`。输入末尾的尾逗号被 SNBT 读取器接受。这份样例的绝对坐标已落在 0–15 内，掩码与否结果相同，因此对两个实现同时成立。

### 样例 2 解释：

打包实现只保存区块内坐标，读 V1 时把 `x`、`z` 按 `&0xF` 折进区块，`19` 变 `3`、`23` 变 `7`；`y` 不掩码而是作范围检查，`256` 与 `-1` 两条越界条目直接丢弃，故答案里没有它们。同一份输入交给装箱实现会得到四条（保留绝对坐标）而不是两条，所以这份样例只能放 `packed/`。

### 样例 3 解释：

装箱实现读打包子格式，走跨格式迁移路径：打包字里的坐标是区块内坐标，装箱实现按文件名区块 `(1,2)` 的基址还原为绝对坐标，`x` 加 `16`、`z` 加 `32`；触发刻为 `baseTime` 加 `delay`。打包实现读同一份输入得到的是未加基址的 `0,10,0`，因此这份样例只能放 `boxed/`。
