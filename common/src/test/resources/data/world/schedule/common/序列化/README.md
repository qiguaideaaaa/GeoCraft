# 测试：方块计划刻调度器-区块-序列化

## 测试描述

该测试用于验证两个区块数据实现把计划刻写成 NBT 的正确性。

测试流程是：把 `.in.yaml` 载入为 `计划刻数据`，逐条入队，调用 `markDirty()`（否则 `serializeNBT` 可能直接返回缓存），取 `serializeNBT()` 的结果，再用 `.ans.snbt` 解析出的复合标签经 `NBTMatcher.toMatcher(expected,true)` 构造严格匹配器去匹配它。严格匹配要求键集合精确相等、列表与数组按多重集合比较，因此答案要写全所有键，但不必关心 `queue` 数组与 `entries` 列表的内部顺序。

本 README 覆盖 `packed/序列化/` 与 `boxed/序列化/` 下的全部样例。

### 本目录为空的原因

`common/序列化/` 是共享序列化样例的预留位置，两个测试类都会扫描它，但当前没有样例文件——两个实现写出的 NBT 形态本身不同（打包写 `queue` 长整型数组，装箱写 `entries` 复合标签列表），同一份 `.ans.snbt` 无法同时匹配两者；输入侧的坐标语义也不同（见下）。因此现有样例全部放在 `packed/序列化/` 与 `boxed/序列化/` 专属目录。

### 双实现语义差异现状

| 项目 | 打包实现 | 装箱实现 |
|---|---|---|
| 入队接口 | `schedule(世界总时间, cx, cy, cz, 方块ID, 延迟, 优先级)` | `schedule(计划刻)` |
| 输入 `于` 的 `x`、`z` 分量 | 区块内坐标（0–15），实现不涉及区块 | 绝对坐标，入队前断言落在文件名区块的 16×16 范围内 |
| 文件名区块坐标 | 不带、也不解析 | 必带，用来构造所在区块的 `EmptyChunk` |
| NBT 键 `baseTime` 的取值 | 首次入队那一刻的世界总时间 | 序列化那一刻的世界总时间 |
| `baseTime` 是否总会写出 | 队列为空（从未入队）时，`queue` 与 `baseTime` 两个键都不写 | 无条件写出 |
| 写出的延迟 | `delay` 位段，按无符号存 | `t` 字段，为 `(int)(触发刻 - 世界总时间)` |
| 写出的坐标 | `x`、`z` 位段即输入的区块内坐标 | `p` 里的 `x`、`z` 位段为绝对坐标 `&0xF`，`y` 占满低 32 位、无范围限制 |

在本测试里，入队与序列化都发生在输入 `time` 指定的同一时刻（打包实现入队时把 `time` 当作当时的世界总时间传入；装箱实现的模拟世界总时间被设为 `time`），因此两个实现写出的 `baseTime` 都等于 `time`，答案照此书写即可。

## 输入格式

输入是一个 `.in.yaml` 文件，即一份 `计划刻数据`，字段见 `data.schema.json`：

- `time`：世界总时间——本测试中入队与序列化都发生在这一刻；
- `ticks`：要入队的计划刻列表，每项写 `x`、`y`、`z`、`块`、`时`（绝对触发刻），`级` 可省略（缺省 `中上7`）。

延迟不直接书写，由 `时` 减 `time` 得出。

## 答案格式

答案是一个 `.ans.snbt` 文件，内容为期望写出的完整复合标签，`#` 起的注释在读取时被截去。

打包实现的答案形态：

- `version`：`2`；
- `type`：`1b`；
- `baseTime`：`Long`；
- `queue`：`[L;...]`，每个元素用 `tick(delay,级,pos,词块)` 写出，`pos` 为区块内坐标。

装箱实现的答案形态：

- `version`：`2`；
- `type`：`0b`；
- `baseTime`：`Long`；
- `entries`：复合标签列表，每项写 `i`（`blockOf(词块)`）、`p`（`packPosAndPri(级,pos)`，`pos` 的 `x`、`z` 为区块内坐标，`y` 原样）、`t`（相对 `baseTime` 的延迟）。

`baseTime` 写成无符号长整型字面量（如 `1000uL`）：严格匹配比较 NBT 类型，写成 `Int` 会失配。

## 输入输出样例 #1

### 输入 #1

`packed/序列化/测试基本序列化.in.yaml`：

```yaml
time: 1000
ticks:
  - 于: [1, 1, 1]
    块: 〇
    时: 1001
```

### 答案 #1

```
{
    type:1b,
    version:2,
    baseTime:1000uL,
    queue:[L;tick(1u,7b,[I;1,1,1],"〇")]
}
```

## 输入输出样例 #2

### 输入 #2

`boxed/序列化/测试基本序列化.0.0.in.yaml`，内容与样例 #1 的输入相同。

### 答案 #2

```
{
    type:0b,
    version:2,
    baseTime:1000uL,
    entries:[
        {
            p:packPosAndPri(7b,[I;1,1,1]),
            t:1,
            i:blockOf("〇")
        }
    ]
}
```

## 说明/提示

### 样例 1 解释：

一条计划刻在世界总时间 `1000` 时入队、`1001` 触发，延迟为 1，优先级缺省 `中上7`（位段值 7）。打包实现把它压成一个 `long` 放进 `queue`，`baseTime` 取首次入队时的世界总时间 `1000`。

### 样例 2 解释：

同一份输入交给装箱实现，写出的是 `entries` 列表里的一个复合标签：`t` 为 `1`、`p` 由优先级与坐标打包、`i` 为方块 ID，`type` 也换成 `0b`。两份答案的形态不同——这正是两个实现无法共用同一份序列化答案的直接体现。这份样例的区块坐标是 `(0,0)`，故输入的绝对坐标与 `p` 内的区块内坐标数值相同。
