# 测试：方块计划刻调度器-调度

## 测试描述

该测试驱动方块计划刻调度器的四个组合——实现分打包（`Packed`）与装箱（`Boxed`），顺序保证分偏序（`PartialOrder`，只保证区块内部顺序）与全序（`TotalOrder`，跨区块也保证顺序），即 `PartialOrderPackedBlockTickScheduler` 等四个类——在模拟区块世界里逐刻运行，验证计划刻的入队与消费行为本身。装箱侧使用扩展模拟区块世界，y 超出 0–255 的方块也能放置与读回。与（反）序列化测试验证数据的静态往返不同，这里的样例是一段写给调度器执行的程序：方块之间有因果交互，终态网格是唯一的断言。设计难度在于元件之间的因果依赖：改动任何一处都要重新推演全部故障路径的结局。

测试使用四种专用方块：

- **猹**（词块 `猹0`–`猹9`、`猹a`–`猹f`，下标即 `_出现时间_`）：被消费时**仅当** `当前时间 & 0xF == 出现时间` 才自清为 〇，否则原地不动。它相当于一个 4 位寄存器，状态记录自己应当在哪个时刻被清除；错过、提前或错误时刻的消费都会让它留在原地导致测试失败。
- **鲁**（减一）/ **讯**（加一）：被消费时把方位内相邻的猹的出现时间拨动一格（mod 16）。下标即方位：`x` 下、`o` 上、`λ` 北、`v` 南、`э` 西、`e` 东、`4` 水平四方、`6` 全六面；裸 `鲁` 即 `鲁6`。它本身不留任何可断言的痕迹、不产生新计划、不自毁，所有效果都体现为猹的出现时间被拨动。
- **闰土**（词块下标即延迟：`閏8`–`閏1` 为 −8..−1、`閏0`/`闰0` 为 0、`闰1`–`闰7` 为 +1..+7；裸 `閏` 即 `閏1`、裸 `闰` 即 `闰1`）：唯一在**消费中途**调用 `schedule` 的方块——驱动器的入队检查发生在消费之前，这条重入路径只有它能走到。被消费时看上方：若为 〇，先给自己排一条延迟为下标的计划，**再**往上方种一只猹（出现时间 = (当前时间+延迟)&0xF）；否则断言上方与下方的方块状态相等，失败即测试当场报错、消息带时间戳。它本身不自毁，残留在终态网格里不算失败。两条分支对应两条故障通道：种植分支把时序类故障转成终态幸存者，断言分支把状态不一致转成即时红。
- 各方块组合可以编码因果链：调度器的丢失、重复、乱序、错时消费都会让猹的出现时间对不上，在终态网格里留下未被清除的猹。

**判定**：全部时段跑完后导出网格，任何位置仍是猹方块即失败，报层/行/列。

## 样例格式

每个样例是一对同名文件，测试按 `.格` 扩展名发现并配对。公共环境（编码、SNBT/YAML 语法、时间的环语义、坐标约定）见上层的 `README.md`（`data/world/schedule/`）。

样例目录按【实现 × 顺序保证】两个正交维度划分：实现分 `common/`（打包、装箱共用）与 `packed/`、`boxed/`（单实现）；顺序保证分 `调度/`（偏序、全序共用）与 `偏序调度/`、`全序调度/`（单序）。如 `common/调度/` 被全部组合跑，`common/全序调度/` 被两实现的全序跑，`packed/调度/`、`boxed/调度/` 各被对应实现的两种顺序跑。归属判据是被测性质：不依赖实现细节的放 `common/`；一类组合作出保证、在其他组合属实现细节的（如过期条目的消费顺序、跨区块的同刻顺序），只在作保证的目录立样例——目录即断言的一部分，偏序跑全序样例红是预期而非缺陷。

`.格` 文件为三段式：front-matter（两条 `---` 之间的 YAML）、词块网格正文（层间空行分隔，`略`/`略N` 跳层填默认，`#` 起注释）、第三条 `---` 之后的自由文档区（解析器不读，短说明直接写在这里）。front-matter 需填写：

- `name`：样例名，带目录层级前缀：`通用/打包/装箱-[全序调度/偏序调度-]<名字>`（普通 `调度` 目录不带中段，如 `通用-闰土`、`通用-全序调度-严厉的鲁迅`、`打包-大存储值`）；
- `ver`：版本，填 `1`；
- `default`：缺省填充词块；
- `ext.测试时段`：区间列表，每项 `[a, b]` 相对 `time`，驱动方式见下。

`.yaml` 文件为 `计划刻数据`：

- `time`：初始世界时间，缺省 `0`；
- `原点` 与 `使用网格坐标`：见上层 `README.md`（`data/world/schedule/`）的 data.schema.json 一节；
- `ticks`：计划列表，每条必填 `于`、`块`、`时`，可选 `级` 与 `创时`（入队时刻，缺省 `0`）。

**驱动方式**：世界时间从 `time` 起。对 `测试时段` 的每个区间 `[a, b]`：时钟先跳到 `time+a`，然后逐刻执行"入队检查 → 消费 → 时钟 +1"，直到当前时间等于 `time+b`。终点刻既不做入队检查也不执行更新；区间之间时钟直接跳到下一区间起点，可用于跨越大时段（如重设基准时间所需的 2^31 级间隔）。入队检查按**严格相等**：`创时 == 当前时间` 的条目在该刻入队——**`time` 非零的样例必须给每条计划显式写创时**，否则永不入队。入队走 `schedule(IScheduledTick)`：`时 − 创时` 的差值经入口压缩为 int，超出 int 范围会被压成 `Integer.MIN_VALUE`，条目入队即到期——想让条目在遥远未来触发，必须让创时跟着挪过去。

**头号陷阱**：环语义下时刻没有大小可比，区间终点判定用不等号。代价是 `time+b` 必须恰好落在从 `time+a` 出发逐刻 +1 的路径上：`(b − a) mod 2^64` 不是小正数时，循环要绕行环上最多一整圈（2^64 次迭代）才停，线程等同卡死。写样例时每个区间都要手工验算时间差，跨符号翻转点、归零点的样例尤其如此；本地跑测试若十分钟无响应，第一反应是检查时间差算术而不是重跑。

## 说明/提示

### 样例 1 解释：

五只猹按 `时 0..4` 错开触发刻，下标与各自的触发刻一致。时段 `[0,5]` 内每刻消费一条，t=0 至 t=4 依次命中自清；任何一条丢失、提前或迟后都会让对应的猹留在原地。

### 样例文档

因果链复杂的样例另配 `<名>.md` 独立文档（时间线推演 + 故障→现场对照表），简单样例可不配。AI 生成的 `.格` 在 front-matter 第二行以注释标记 `# Claude Generated`。

### 样例设计法则

三条硬标准：

1. **敏感**——样例的每个元素都必须是绿色的必要条件。被测环节失效而测试仍绿，比误报严重得多；设计完成后逐个自问"删掉这条计划/这只猹，还测得到原目标吗"。
2. **清晰**——红了之后，由幸存者的位置与状态能唯一反推断裂环节；多种故障映射到同一现场即不合格。
3. **小**——网格、计划条目、时段全部最小化。大样例不是覆盖广，是自由度失控。

由三条标准推出的操作纪律：

#### 布局与算术

- **mod 16 同余纪律**：单个时段窗口不超过 16 刻时，窗口内任何"错误时刻"都不会与猹的出现时间同余，错时消费必被察觉。窗口更长或多时段时须逐点验算同余。
- **对照刻**：只含过期/当刻计划的样例分辨不出"全部立即消费"型退化实现——加一条正常的未来计划作对照，退化实现会提前消费它。
- **不同出现时间的猹分线**：一个样例测多个性质时，用出现时间互不相同的猹把它们拆成独立算术线，每线各配预算——共用一条线的性质互相遮蔽，红了无法定位。
- **补救按线分配**：补救指为正确路径善后的后续清除计划，它会顺带掩盖本该报错的故障。哪条线允许晚到、哪条线错过即失败，必须逐线显式决定；不设补救的线才能检出顺序类故障。
- **错峰绑定**：多条计划错开触发刻并让出现时间与触发刻一一对应，任何时序错排都自然不同余。
- **不对称布局**：几何上对称的猹阵在坐标互换类解码故障下会映回自身（整体绿）。布局至少要在一个轴向上不对称，或由另一样例的不对称布局兜底。
- **计数器手法**：鲁/讯的每次触发都拨动猹一格，"被触发了几次"因此成为可断言的量——按计划内的拨动总数选定猹的初始状态，清除刻只在恰好这么多次拨动后同余，多一次少一次都留下幸存者（鲁迅、讯增样例即此手法）。适用面有边界：可察觉的是鲁/讯条目在清除刻之前的重复触发；猹自身条目的重复消费仍不可见，见盲区节。
- **再入队探针**：计划条目出队后，对同一（区块内坐标, 方块）再次入队，可探测入队去重集的残留——去重键不含触发刻与优先级，出队时忘了移除键，第二次入队就被静默拒绝，拨动少一次、清除刻不同余（讯增样例即此探针）。
- **终点不更新**：时段 `[a, b]` 的 b 刻既不做入队检查也不消费，可用来表达"到此为止不该再发生"：把不希望发生的消费排在终点刻，差一刻的实现会把它消费掉。注意条目并未被丢弃——后续时段的首刻会把它当过期条目消费（重设基准时间样例的旧条目正是这样被收走的），所以这个手法只在最后一个时段闭合。该手法的两面都有样例在用：闰土样例的时序类故障路径把种植级联截断在终点刻、转换成幸存者；中途重设样例用其延后一面——终点刻遗留的条目由下一时段首刻当过期条目收走。

#### 验证与合成故障

- **前提检查线**：样例的结论若建立在某个运行前提上（如"消费前未发生重设基准时间"），前提本身也要有一条线来验证——前提被破坏时该线必须变红，否则被测局面根本没发生过、样例成了前提落空的绿（大存储值样例的顺序检查线即此手法：一对严重过期条目的消费顺序在重设归 0 后会因优先级位反转）。
- **复合故障推演**：单点故障逐条推演全红不代表完工——多处同时出错的合成路径可能互相抵消回到绿。逐条验算完故障表后，把最可疑的组合（尤其同一根因的两处，如排序与出队判断同用有符号）也推一遍；发现合成路径漏检时，通常靠调整触发刻的低四位把"提前消费"与"按时消费"区分开（大存储值样例的触发刻取低四位 3 而非 0 即为此）。
- **免测范围**：网格导入、坐标换算这类几行的测试设施代码靠人工审读担保，不为其编写测试——样例的复杂度预算全部花在被测物上。

#### 中途入队与闰土

- **中途入队的时刻口径**：执行中途 schedule 的条目，延迟为负或 0 者不测顺序与时刻——当刻消费与下一刻消费两态皆合法，样例必须构造成两态同绿（断言臂无副作用、下方参照在两刻间不变、两刻内禁注入同键条目）；正延迟者自下一刻边界起受全部保证、必须恰在 创刻+延迟 执行（更新量超限与区块卸载重载的推迟在测试场景不存在，按必需准点断言）。
- **闰土几何与同余**：闰土不放网格顶层，其上方须落在 y 0–255 内（观察者的种植位同理）；每只闰土的样例文档必须有"若上方为〇"故障行并推演归宿；（触发刻+延迟）的低四位须避开预期猹出现时间与该列窗口内一切后续消费刻——观察者闰土故障路径种出的猹也要过这条验算，防被清除线误清而掩盖故障。
- **观察者闰土**：静止参照放上方、被观察位放下方——上方永非〇，断言臂必达，绕开"观察对象缺席时走种植分支静默"的陷阱；文档必须有"观察者自身丢失=沉默"行并论证与被测目标的复合不可达。链式自计划须在窗口内闭合：末次消费走断言臂，逐代触发刻严格落在窗口内部且非终点刻。
- **创时表**：含中途入队的样例必附创时核对：同（位置, 方块）键的队内存活区间不得相交；注入检查先于当刻消费，后条创时须 ≥ 前条消费刻+1。
- **同键探针豁免**：正确路径下被去重静默拒绝、删掉不影响绿的纯探测条目允许使用——这是对"敏感"标准的显式豁免，文档须声明其豁免身份并说明静默拒绝本身就是被测的去重契约。
- **讯中途拨动**（手法记录，不独立立样例）：对种出的猹用讯中途拨动、参照取拨动后状态，可把自计划早到转换为断言失败；检出面已被"参照取第二代状态"手法包含。
- **断言收敛与区块正交**：闰土断言一红即截断后续证据，宜置于因果收敛点，多断言点须各自独立成红；布局须保证目标区块在关键刻不被其他 schedule 触碰——任何入队都可能建立基准时间、触发重设或把被摘的区块重新挂回记账、掩盖记账类故障。

### 新增样例流程

1. 定下被测目标与故障模式清单，确认没有既有样例已覆盖（见下方覆盖地图）；
2. 布置猹：出现时间与预期消费时刻逐个对应，验算窗口内没有低四位相同的两个时刻；
3. 验算每个测试时段的时间差为小正数；
4. 写 `.格` 与 `.yaml`，`time` 非零时逐条补 `创时`；
5. 跑通后做破坏验证：故意改错一个 `时` 确认测试变红，再改回；
6. 复杂样例配文档（时间线推演 + 故障→现场对照表），简单样例可不配。

### 覆盖地图与已知盲区

当前已有样例：

- `common/调度`（全部组合共跑）：A（多刻错峰基础）、同刻齐发（同刻批量）、过期即触（过期/当刻/对照）、跨区块与负区块跨界（正负区块边界）、符号翻转点与跨零（绝对时间环语义入口）、讯增（增一方位与去重再入队）、鲁迅（同刻优先级序、触发计数、严重过期标记值、创时窗口内注入）、闰土（执行中途入队的正延迟自计划、去重方块精细度、双故障通道）、闰土复种（中途自计划的丢失/早到/重复消费，观察者与第二代参照）、閏土（负延迟中途入队不破坏既有同刻顺序，二态双绿构造）、区块摘除（收尾错误清空记账使区块不再被处理——中途入队使本刻结束后队内仍有条目，与自计划无关的既有条目作唯一指认）——闰土复种另含一条同键探针（豁免条目，检测去重键双删）；
- `common/全序调度`（两实现的全序）：严厉的鲁迅（跨区块同刻优先级序，两十字分别横跨 x、z 边界，负区块参与排序）；
- `packed/调度`（打包两序）：重设基准时间（时段跳跃拉开与基准时间的差距）、大存储值（堆内存储值跨 2^31 分界的无符号排序与出队判断，并以一对过期条目的消费顺序确认消费前未重设基准时间）、中途重设（消费中途触发的重设对既有未来条目与已入队未执行的自计划的无损性——单批规模下消费中重设只面对未来条目，归 0 钳制归重设基准时间样例管）；
- `boxed/调度`（装箱两序）：过期顺序（时间差超过 2^31 的跳跃后，过期条目仍按原触发刻顺序消费——打包侧这个量级会重设基准时间、把过期条目一并归 0，原顺序属实现细节，故不立对应样例；小时间差下两实现都按原顺序消费，测不出差别）、越下界y 与 越上界y（y 超出 0–255 的计划刻正常消费，打包实现入队时直接拒绝）、顶替（先数到期数再按名额消费的形态——中途自计划挤占名额使既有条目迟一刻）。

已知且明示接受的盲区：

- **重复消费不可见**：猹自清后位置变 〇，二次消费被消费侧验证跳过、无副作用——"只查存活"的断言形态天然看不见它。交互形态由鲁迅样例的计数线覆盖（多拨一次即错位）。
- **区块处理次序不作构造依据**：多个区块在同一刻内被遍历的先后取自内部集合的迭代序，两侧都属实现细节。偏序侧样例只能依赖单个区块内部的堆序（存储值、优先级）；全序侧可依赖全局归并出的触发刻→优先级序，但不可依赖遍历次序本身。
