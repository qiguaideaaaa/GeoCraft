# 测试：方块计划刻调度器-调度

## 测试描述

该测试驱动方块计划刻调度器的两个实现（打包 `PackedBlockTickScheduler`、装箱 `BoxedBlockTickScheduler`）在模拟区块世界里逐刻运行，验证计划刻的入队与消费行为本身。装箱侧使用扩展模拟区块世界，y 超出 0–255 的方块也能放置与读回。与（反）序列化测试验证数据的静态往返不同，这里的样例是一段写给调度器执行的程序：方块之间有因果交互，终态网格是唯一的断言。设计难度与红石电路同源——元件间的因果让自由度相互纠缠，改动任何一处都要重新推演全部故障路径的结局。

测试使用三种专用方块：

- **猹**（词块 `猹0`–`猹9`、`猹a`–`猹f`，下标即 `_出现时间_`）：被消费时**仅当** `当前时间 & 0xF == 出现时间` 才自清为 〇，否则原地不动。它相当于一个 4 位寄存器，状态记录自己应当在哪个时刻被清除；错过、提前或错误时刻的消费都会让它留在原地导致测试失败。
- **鲁**（减一）/ **讯**（加一）：被消费时把方位内相邻的猹的出现时间拨动一格（mod 16）。下标即方位：`x` 下、`o` 上、`λ` 北、`v` 南、`э` 西、`e` 东、`4` 水平四方、`6` 全六面；裸 `鲁` 即 `鲁6`。它本身不留任何可断言的痕迹、不产生新计划、不自毁，所有效果都体现为猹的出现时间被拨动。
- 两者组合可以编码因果链：调度器的丢失、重复、乱序、错时消费都会让猹的出现时间对不上，在终态网格里留下未被清除的猹。

**判定**：全部时段跑完后导出网格，任何位置仍是猹方块即失败，报层/行/列。

## 样例格式

每个样例是一对同名文件，测试按 `.格` 扩展名发现并配对。公共环境（编码、SNBT/YAML 语法、时间的环语义、坐标约定）见上层的 `README.md`（`data/world/schedule/`）。

样例按实现依赖分三个目录：`common/调度/` 两个实现都跑；`packed/调度/`、`boxed/调度/` 只被对应实现跑。归属判据是被测性质：不依赖实现细节的放 `common/`；一个实现作出保证、而在另一个实现属实现细节的（如过期条目的消费顺序），只在作保证的一侧立样例。

`.格` 文件为三段式：front-matter（两条 `---` 之间的 YAML）、词块网格正文（层间空行分隔，`略`/`略N` 跳层填默认，`#` 起注释）、第三条 `---` 之后的自由文档区（解析器不读，短说明直接写在这里）。front-matter 需填写：

- `name`：样例名；
- `ver`：版本，填 `1`；
- `default`：缺省填充词块；
- `ext.测试时段`：区间列表，每项 `[a, b]` 相对 `time`，驱动方式见下。

`.yaml` 文件为 `计划刻数据`：

- `time`：初始世界时间，缺省 `0`；
- `原点` 与 `使用网格坐标`：见上层 `README.md`（`data/world/schedule/`）的 data.schema.json 一节；
- `ticks`：计划列表，每条必填 `于`、`块`、`时`，可选 `级` 与 `创时`（入队时刻，缺省 `0`）。

**驱动方式**：世界时间从 `time` 起。对 `测试时段` 的每个区间 `[a, b]`：时钟先跳到 `time+a`，然后逐刻执行"入队检查 → 消费 → 时钟 +1"，直到当前时间等于 `time+b`。终点刻既不做入队检查也不执行更新；区间之间时钟瞬移，可用于跨越大时段（如重设基准时间所需的 2^31 级间隔）。入队检查按**严格相等**：`创时 == 当前时间` 的条目在该刻入队——**`time` 非零的样例必须给每条计划显式写创时**，否则永不入队。入队走 `schedule(IScheduledTick)`：`时 − 创时` 的差值经入口压缩为 int，超出 int 范围会被压成 `Integer.MIN_VALUE`，条目入队即到期——想让条目在遥远未来触发，必须让创时跟着挪过去。

**头号陷阱**：环语义下时刻没有大小可比，区间终点判定用不等号。代价是 `time+b` 必须恰好落在从 `time+a` 出发逐刻 +1 的路径上：`(b − a) mod 2^64` 不是小正数时，循环要绕行环上最多一整圈（2^64 次迭代）才停，线程等同卡死。写样例时每个区间都要手工验算时间差，跨符号翻转点、归零点的样例尤其如此；本地跑测试若十分钟无响应，第一反应是检查时间差算术而不是重跑。

## 说明/提示

### 样例 1 解释：

五只猹按 `时 0..4` 错开触发刻，下标与各自的触发刻一致。时段 `[0,5]` 内每刻消费一条，t=0 至 t=4 依次命中自清；任何一条丢失、提前或迟后都会让对应的猹留在原地。

### 样例文档

因果链复杂的样例另配 `<名>.md` 独立文档（时间线推演 + 故障→现场对照表），简单样例可不配。AI 生成的 `.格` 在 front-matter 第二行以注释标记 `# Claude Generated`。

### 样例设计法则

三条硬标准：

1. **敏感**——样例的每个元素都必须是绿色的必要条件。被测环节罢工而测试仍绿，比误报严重得多；设计完成后逐个自问"删掉这条计划/这只猹，还测得到原目标吗"。
2. **清晰**——红了之后，由幸存者的位置与状态能唯一反推断裂环节；多种故障映射到同一现场即不合格。
3. **小**——网格、计划条目、时段全部最小化。大样例不是覆盖广，是自由度失控。

由三条标准推出的操作纪律：

- **mod 16 同余纪律**：单个时段窗口不超过 16 刻时，窗口内任何"错误时刻"都不会与猹的出现时间同余，错时消费必被察觉。窗口更长或多时段时须逐点验算同余。
- **对照刻**：只含过期/当刻计划的样例分辨不出"全部立即消费"型退化实现——加一条正常的未来计划作对照，退化实现会提前引爆它。
- **不同出现时间的猹分线**：一个样例测多个性质时，用出现时间互不相同的猹把它们拆成独立算术线，每线各配预算——共用一条线的性质互相遮蔽，红了无法定位。
- **补救按线分配**：补救指为正确路径善后的后续清除计划，它会顺带掩盖本该报错的故障。哪条线允许晚到、哪条线错过即失败，必须逐线显式决定；不设补救的线才能检出顺序类故障。
- **错峰绑定**：多条计划错开触发刻并让出现时间与触发刻一一对应，任何时序错排都自然不同余。
- **不对称布局**：几何上对称的猹阵在坐标互换类解码故障下会映回自身（整体绿）。布局至少要在一个轴向上不对称，或由另一样例的不对称布局兜底。
- **计数器范式**：鲁/讯的每次触发都拨动猹一格，"被触发了几次"因此成为可断言的量——按计划内的拨动总数选定猹的初始状态，清除刻只在恰好这么多次拨动后同余，多一次少一次都留下幸存者（鲁迅、讯增样例即此手法）。适用面有边界：可察觉的是鲁/讯条目在清除刻之前的重复触发；猹自身条目的重复消费仍不可见，见盲区节。
- **再入队探针**：计划条目出队后，对同一（区块内坐标, 方块）再次入队，可探测入队去重集的残留——去重键不含触发刻与优先级，出队时忘了移除键，第二次入队就被静默拒绝，拨动少一次、清除刻不同余（讯增样例即此探针）。
- **终点不更新**：时段 `[a, b]` 的 b 刻既不做入队检查也不消费，可用来表达"到此为止不该再发生"：把不希望发生的消费排在终点刻，差一刻的实现会引爆它。注意条目并未被丢弃——后续时段的首刻会把它当过期条目消费（重设基准时间样例的旧条目正是这样被收走的），所以这个手法只在最后一个时段闭合。目前尚无样例使用，属备用手法。
- **前提检查线**：样例的结论若建立在某个运行前提上（如"消费前未发生重设基准时间"），前提本身也要有一条线来钉住——前提被破坏时该线必须变红，否则被测局面根本没发生过、样例成了前提落空的绿（大存储值样例的顺序检查线即此手法：一对严重过期条目的消费顺序在重设归 0 后会因优先级位反转）。
- **复合故障推演**：单点故障逐条推演全红不代表完工——多处同时出错的合成路径可能互相抵消回到绿。逐条验算完故障表后，把最可疑的组合（尤其同一根因的两处，如排序与出队判断同用有符号）也推一遍；发现合成路径逃逸时，通常靠调整触发刻的低四位把"提前消费"与"按时消费"区分开（大存储值样例的触发刻取低四位 3 而非 0 即为此）。
- **免测范围**：网格导入、坐标换算这类几行的测试设施代码靠人工审读担保，不为其编写测试——样例的复杂度预算全部花在被测物上。

### 新增样例流程

1. 定下被测目标与故障模式清单，确认没有既有样例已覆盖（见下方覆盖地图）；
2. 布置猹：出现时间与预期消费时刻逐个对应，验算窗口内没有低四位相同的两个时刻；
3. 验算每个测试时段的时间差为小正数；
4. 写 `.格` 与 `.yaml`，`time` 非零时逐条补 `创时`；
5. 跑通后做破坏验证：故意改错一个 `时` 确认测试变红，再改回；
6. 复杂样例配文档（时间线推演 + 故障→现场对照表），简单样例可不配。

### 覆盖地图与已知盲区

当前已有样例——`common/`（两实现共跑）：A（多刻错峰基础）、同刻齐发（同刻批量）、过期即触（过期/当刻/对照）、跨区块与负区块跨界（正负区块边界）、符号翻转点与跨零（绝对时间环语义入口）、讯增（增一方位与去重再入队）、鲁迅（同刻优先级序、触发计数、严重过期标记值、创时中途入队）；`packed/`：重设基准时间（时段跳跃拉开与基准时间的差距）、大存储值（堆内存储值跨 2^31 分界的无符号排序与出队判断，并以一对过期条目的消费顺序确认消费前未重设基准时间）；`boxed/`：过期顺序（时间差超过 2^31 的跳跃后，过期条目仍按原触发刻顺序消费——打包侧这个量级会重设基准时间、把过期条目一并归 0，原顺序属实现细节，故不立对应样例；小时间差下两实现都按原顺序消费，测不出差别）、越下界y 与 越上界y（y 超出 0–255 的计划刻正常消费，打包实现入队时直接拒绝）。

已知且明示接受的盲区：

- **重复消费不可见**：猹自清后位置变 〇，二次消费被消费侧验证跳过、无副作用——"只查存活"的断言形态天然看不见它。交互形态由鲁迅样例的计数线覆盖（多拨一次即错位）。
- **区块处理次序不作构造依据**：多个区块在同一刻内的处理先后取自内部集合的迭代序，属实现细节——样例只能依赖单个区块内部的堆序（存储值、优先级）。
- **单刻更新数量上限不测**：限额的分批切点由各实现的批粒度决定（区块内单批出队上限、收集粒度等），属实现形态而非规范；可行的样例形态曾要求百条级规模且随架构变化而失效，明示放弃。
